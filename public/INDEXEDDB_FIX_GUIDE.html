إصلاح تحديث حالة الملفات في IndexedDB

تم إصلاح المشكلة!

الآن عند رفع الملفات بنجاح، يتم تلقائياً تحديث حالتها في IndexedDB من "pending" أو "uploading" إلى "completed" ✅

المشكلة السابقة

  • الملفات تُرفع بنجاح للسيرفر
  • لكن حالتها في IndexedDB تبقى pending أو uploading
  • عند إعادة فتح الصفحة، تظهر كأنها لم تُرفع
  • المستخدم يضطر لرفعها مرة أخرى!

الحل المطبق

1. ملف جديد: file-storage-indexeddb.js جديد

يدير تخزين وتحديث حالة الملفات في IndexedDB:

  • saveFile(fileData) - حفظ/تحديث ملف
  • updateFileStatus(fileId, status) - تحديث الحالة
  • getFile(fileId) - جلب ملف معين
  • getAllFiles() - جلب جميع الملفات
  • getFilesByStatus('completed') - جلب حسب الحالة
  • getStats() - إحصائيات الملفات
2. تحديث upload-status-sync.js

إضافة تحديث تلقائي لـ IndexedDB عند تغير حالة الملف:

// عند استقبال event من FileSyncWorker async function handleUploadStatusChange(event) { const { fileId, status, error } = event; if (status === 'completed') { // 💾 تحديث IndexedDB ← الحل! await updateIndexedDBStatus(fileId, 'completed'); // 🎨 تحديث الواجهة updateFileUIToSuccess(fileId); } }

حالات الملفات المدعومة

الحالة الوصف Icon اللون
pending في انتظار الرفع ⏳ أصفر
uploading جاري الرفع الآن ⏳ أزرق
completed تم الرفع بنجاح ✅ ✅ أخضر
failed فشل الرفع ❌ أحمر

الفوائد

  • لا تكرار: الملفات المرفوعة لا تُطلب مرة أخرى
  • استمرارية: الحالة محفوظة حتى بعد إغلاق التطبيق
  • شفافية: المستخدم يرى الحالة الصحيحة دائماً
  • تلقائي: لا حاجة لتحديث يدوي
  • دقة: مزامنة فورية مع FileSyncWorker
