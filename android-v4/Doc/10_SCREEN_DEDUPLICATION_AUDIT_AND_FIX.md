# 10 — تدقيق وتوحيد الشاشات المكرَّرة (كل الأنواع)

القرار المعتمد: **معالجة كل أنواع التكرار سوا** — شاشات/ملفات مكررة، روابط مكررة بالقائمة الجانبية (AdminNav)، وتكرار كود/API خلف الكواليس.

## 1. التكرار المؤكَّد من كتالوج الشاشات (08) — 3 أزواج

نتيجة مباشرة لبناء "الشاشات الأساسية" (القسم أولاً) ثم "شاشات لوحة التحكم v3" (القسم ثالثاً) في نفس المرحلة 5 بدون مطابقة صريحة بينهما أولاً:

| # | الزوج المكرَّر | الملفات المتورطة | القرار |
|---|-----------------|---------------------|--------|
| 1 | إدارة الكفالات (#2) ↔ كل الكفالات + المكفولين/غير المكفولين (#19-20) | `admin/sponsorships.html` مقابل نفس الملف مذكور بتبويبات موسَّعة | **دمج**: شاشة واحدة `admin/sponsorships.html` بتبويبات (الكل / مكفولين / غير مكفولين) — لا ملف ثانٍ |
| 2 | إدارة الصلاحيات (#4) ↔ المستخدمون + الأدوار (#22) | `admin/roles.html` + `admin/users.html` **بالحرف نفس الملفين مذكورين مرتين** | **لا يوجد تكرار فعلي بالملفات** — تكرار توثيقي فقط بالكتالوج (نفس الملفين سُجِّلا تحت عنوانين). **الإصلاح: توثيقي فقط** — دمج السطرين لسطر واحد بالكتالوج |
| 3 | إدارة الملفات (#5) ↔ بوابة/مجلدات/مكررات/تدقيق (#23) | `admin/files.html` + `folders` + `duplicates` + `attachment-audit` مذكورة مرتين بوصفين مختلفين | **لا يوجد تكرار فعلي بالملفات** — نفس السبب: تكرار توثيقي. **الإصلاح: توثيقي فقط** |

**خلاصة مهمة:** الزوج #1 فقط يحتاج تحقق فعلي من احتمال وجود ملف/route مكرر حقيقي (Sponsorships)؛ الزوجان #2 و#3 على الأرجح تكرار في التوثيق نفسه (سطرين بالجدول لنفس الملف) وليس بالكود — لازم نتحقق بالأمر بالقسم 3 أدناه قبل الحكم النهائي.

## 2. تكرار محتمل بالقائمة الجانبية (AdminNav)

`admin-nav.js` هو المصدر الوحيد المفروض لتوليد الروابط. الخطر: لو تم `AdminNav.mount()` باستدعاءين مختلفين على نفس الصفحة، أو لو فيه رابطين بنفس `href` بمصفوفة الروابط داخل `admin-nav.js` بأسماء عرض مختلفة (زي "الكفالات" و"المكفولين") يوديان لنفس `sponsorships.html`.

### أمر تحقق فوري (شغّله على السيرفر)
```bash
cd /var/www/html/alhayahorphans/android-v4/mobile-app-v4/src/js
grep -n "href" admin-nav.js | sort | uniq -c -d  # روابط مكررة بنفس النص بالضبط
grep -n "\.html" admin-nav.js  # كل الروابط — راجعها يدوياً لتكرار منطقي (مسميات مختلفة لنفس الملف)
```

## 3. تكرار بالكود/API خلف الكواليس

### 3.1 خطر تكرار استدعاء نفس البيانات
`admin-api.js` (طبقة API الموحدة) مقابل استدعاءات مباشرة قديمة (لو أي شاشة من الست الأساسية بقيت تستخدم استدعاء `fetch()` مباشر بدل `admin-api.js` بعد ما انبنى `AdminCrudControllerV4`).

### أمر تحقق فوري
```bash
cd /var/www/html/alhayahorphans/android-v4/mobile-app-v4/src
# أي شاشة لسا فيها fetch() مباشر بدل استخدام admin-api.js
grep -rn "fetch(" admin/ screens/ | grep -v "admin-api.js"
```

### 3.2 خطر تكرار تسجيل routes ضمن v4 نفسها (وليس القديم)
بما إنه `api_v4.php` انبنى بمرحلتين منفصلتين (المرحلة 2: `SyncControllerV4` وغيره، ثم المرحلة 5: `AdminCrudControllerV4` بـ59 مسار إضافي) — احتمال تسجيل نفس المسار (مثلاً `GET /api/mobile/v4/admin/reports-source`) مرتين بمتحكمين مختلفين.

### أمر تحقق فوري (الأهم — يكشف تكرار Laravel routes مباشرة)
```bash
cd /var/www/html/alhayahorphans
php artisan route:list --path=api/mobile/v4 | awk '{print $3, $4}' | sort | uniq -d
# لو رجّع أي سطر = فيه تكرار تسجيل route فعلي داخل v4 نفسها (خطأ لازم يُصلَح فوراً)
```

## 4. خطة الإصلاح بالترتيب

1. **شغّل الأوامر الثلاثة بالأقسام 2 و3 أعلاه** وابعتلي النتائج — هاد يحدد هل التكرار توثيقي بس أو فعلي بالكود.
2. **إذا تكرار فعلي بملف/route:** يُدمَج لنسخة واحدة (تبويبات بدل ملفين، أو حذف تسجيل route المكرر مع إبقاء الأحدث فقط لأنه v4 بالكامل وملفاتنا نحن — الإصلاح هون **مسموح ومُستحسَن** لأنه ضمن ملفات v4 الجديدة، وليس ملفات v3/الموقع القديمة المحظور لمسها).
3. **إذا تكرار توثيقي بس (الأرجح للزوجين #2 و#3):** تُحدَّث `08_NEW_SCREENS_CATALOG.md` بدمج السطرين المكررين لسطر واحد لكل شاشة، بدون أي تغيير على الكود.
4. **توحيد AdminNav:** مصفوفة روابط واحدة مركزية بـ`admin-nav.js`، بدون أي تكرار بالمسميات، وأي شاشة اتدمجت (كفالات مثلاً) بتاخذ سطر واحد بس بالقائمة.
5. **توحيد طبقة API:** أي شاشة لسا مستخدمة `fetch()` مباشر تُحوَّل لاستخدام `admin-api.js` حصراً — طبقة وصول بيانات واحدة موحّدة لكل الشاشات.

### إصلاحات مُنفَّذة

1. **`civil-import.html`** — نُقل `fetch` المباشر إلى `AdminAPI.downloadCivilTemplate()` + `AdminAPI.validateCivilImport()` (أُضيفا بطبقة `admin-api.js`). صفر fetch خارج الطبقة الآن.
2. **`08_NEW_SCREENS_CATALOG.md`** — دُمج السطران المكرران:
   - #4 أصبح: «إدارة الصلاحيات + المستخدمون + الأدوار … **دمج مع #22**»
   - #5 أصبح: «إدارة الملفات (بوابة/مجلدات/مكررات/تدقيق) … **دمج مع #23**»
   - #22 و#23 أصبحتا مُشار إليهما كمدمجين فقط (لا سطر فعلي منفصل).
3. **`sponsorships.html` × 3 (base + tab=sponsored + tab=unsponsored)** — تبويبات مقصودة على نفس الملف = مطابقة للقرار (شاشة واحدة بتبويبات). **ليس تكراراً**.
