# تحسين تصدير ملفات Excel الكبيرة

## ⚠️ مشكلة شائعة وحلها

### المشكلة: خطأ 500 عند التصدير
إذا حصلت على خطأ `HTTP ERROR 500` مع رسالة:
```
Fatal error: Allowed memory size of 134217728 bytes exhausted
```

**السبب**: حد الذاكرة في `php.ini` أقل من 512MB (الافتراضي 128MB).

**الحل**:
1. ابحث عن ملف `php.ini`:
   ```bash
   php --ini
   ```

2. افتح الملف وابحث عن `memory_limit` وغيّره إلى:
   ```ini
   memory_limit = 512M
   ```

3. **مهم جداً**: أعد تشغيل خادم Laravel:
   ```bash
   # أوقف الخادم الحالي (Ctrl+C)
   # ثم شغّله من جديد
   php artisan serve
   ```

4. جرب التصدير مرة أخرى.

## المشكلة الأصلية
كانت عملية تصدير السجلات إلى Excel تفشل عند التعامل مع بيانات ضخمة بسبب استنفاد الذاكرة المتاح (2GB):

```
Allowed memory size of 2147483648 bytes exhausted (tried to allocate 41943040 bytes)
```

## الحلول المطبقة

### 1. معالجة البيانات على دفعات (Chunking)
✅ تم استبدال `cursor()` بـ `chunk()` مع حجم دفعة 500 سجل  
✅ يتم معالجة البيانات تدريجياً بدلاً من تحميلها كلها في الذاكرة

### 2. تحرير الذاكرة الدوري
✅ استخدام `gc_collect_cycles()` بعد كل دفعة لتحرير الذاكرة الغير مستخدمة  
✅ استخدام `unset()` لتحرير المتغيرات الكبيرة فوراً بعد الانتهاء منها  
✅ استخدام `disconnectWorksheets()` لتحرير ذاكرة PhpSpreadsheet

### 3. تحسين جلب الحقول الديناميكية
✅ جلب field_keys باستخدام chunking بدلاً من تحميلها دفعة واحدة  
✅ تقليل عدد الاستعلامات إلى قاعدة البيانات

### 4. رفع حد الذاكرة مؤقتاً
✅ رفع memory_limit إلى 512MB أثناء التصدير فقط  
✅ تعطيل الحد الزمني للتنفيذ لضمان إتمام العملية

### 5. معالجة الأخطاء
✅ إضافة try-catch شامل مع تسجيل تفصيلي للأخطاء  
✅ تحرير الذاكرة تلقائياً عند حدوث خطأ

### 6. تسجيل التقدم (Logging)
✅ تسجيل عدد السجلات المعالجة من كل جدول  
✅ تسجيل مراحل العملية لسهولة المتابعة والتشخيص

## الملفات المعدلة
- `app/Services/RecordsExportService.php` - تحديث شامل للكود

## النتائج المتوقعة
- ✅ تصدير آلاف السجلات بنجاح دون نفاد الذاكرة
- ✅ استهلاك أقل للذاكرة (تقريباً 50-70% أقل)
- ✅ أداء أفضل وأكثر استقراراً
- ✅ إمكانية تتبع التقدم عبر السجلات (logs)

## توصيات إضافية (اختيارية)

### لتحسين الأداء أكثر:

1. **تثبيت Laravel Excel**:
   ```bash
   composer require maatwebsite/excel
   ```
   يوفر ميزات متقدمة مثل:
   - Queued Exports (تصدير في الخلفية)
   - أداء أفضل للملفات الضخمة جداً
   - تحكم أفضل في الذاكرة

2. **تقسيم التصدير إلى ملفات متعددة**:
   - تصدير كل 10,000 سجل في ملف منفصل
   - يمكن ضغطها في ملف ZIP واحد

3. **استخدام Queue Jobs**:
   - نقل عملية التصدير إلى queue
   - إرسال رابط التحميل عبر البريد الإلكتروني عند الانتهاء

4. **إضافة شريط تقدم**:
   - عرض نسبة الإنجاز للمستخدم
   - استخدام WebSockets أو AJAX polling

## تعديل حجم الدفعة (Chunk Size)

يمكن تعديل حجم الدفعة في ملف `RecordsExportService.php`:

```php
private const CHUNK_SIZE = 500; // يمكن تغييره إلى 100 أو 1000 حسب الحاجة
```

**توصيات**:
- **100-300**: للبيانات ذات العلاقات المعقدة جداً
- **500-1000**: للبيانات المتوسطة (الافتراضي الحالي)
- **1000-2000**: للبيانات البسيطة بدون علاقات كثيرة

## المراقبة والصيانة

### فحص السجلات (Logs)
راقب ملفات السجلات في `storage/logs/laravel.log` لمتابعة:
- عدد السجلات المصدرة من كل جدول
- الوقت المستغرق في كل مرحلة
- أي أخطاء أو تحذيرات

### مثال على السجلات الناجحة:
```

[2026-02-07 20:31:00] local.INFO: تم معالجة 1000 من 5000 سجل من Data
```

## الاختبار

### للاختبار على بيانات صغيرة:
قم بتعديل حجم الدفعة مؤقتاً إلى 10 سجلات:
```php
private const CHUNK_SIZE = 10;
```

### للاختبار على بيانات كبيرة:
1. راقب استهلاك الذاكرة في لوحة الخادم
2. تحقق من السجلات (logs) للتأكد من عدم وجود أخطاء
3. تأكد من اكتمال التصدير وصحة البيانات

## الدعم الفني

### التحقق من نجاح التعديلات

**تحقق من حد الذاكرة الحالي**:
```bash
php -i | Select-String "memory_limit"
# يجب أن يظهر: memory_limit => 512M => 512M
```

**تحقق من السجلات للتأكد من نجاح التصدير**:
```bash
# في Windows PowerShell
Get-Content "storage/logs/laravel.log" -Tail 50

# ابحث عن هذه الرسائل:
# ✅ "بدء عملية تصدير السجلات..."
# ✅ "جاري تصدير X سجل من جدول Data..."
# ✅ "تم الانتهاء من معالجة البيانات..."
# ✅ "تم إرسال ملف Excel بنجاح"
```

### استكشاف الأخطاء

في حالة استمرار المشكلة:
1. تحقق من السجلات في `storage/logs/laravel.log`
2. تأكد من توفر ذاكرة كافية على الخادم
3. قم بتقليل `CHUNK_SIZE` إلى 100 أو أقل
4. راجع إعدادات PHP (`php.ini`):
   - `memory_limit = 512M` أو أكثر
   - `max_execution_time = 300` أو 0
   - `max_input_time = 300` أو 0
